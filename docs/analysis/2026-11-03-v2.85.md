# v2.85 — Ein Host, der einen Stack nicht kann

issue: #373
tier: 3

## Anlass

Downstream (Kenni #2844) kann ein Mac-Agent den Backend-Stack nicht ausführen: Der Preflight des Projekts fällt dort durch (`pidfd` fehlt, `df` unlesbar), und die Suite ist auf diesem Host nicht bestehbar. Jeder Branch-Push, der den Stack wählt, wird mit Exit 2 abgewiesen. Der einzige Weg vorbei ist `PROCESS_SKIP=tests` mit dem Wort des Owners. Das ist an einem Tag dreimal passiert (#2840, #2843, #2845). Die Merge-Suite fährt ohnehin der Zug auf dem Gate-Host; der Skip schützt nichts und kostet nur Rückfragen.

Owner-Entscheidung: „stimme den Vorschlägen zu“. Das Template liefert die Host-Bedingung je Stack, den Vermerk „fällig auf dem Gate-Host“ und einen Pflichtgrund für `PROCESS_SKIP`. Kenni repariert seinen Preflight und konfiguriert die Stacks.

## Umfang

| Paket | Inhalt |
|---|---|
| H | Host-Bedingung je Stack: Ein Stack, den der Host nicht kann, wird beim Branch-Push vermerkt statt abgewiesen. Merge-Push und Zug bleiben unverändert. |
| S | `PROCESS_SKIP` braucht einen Grund im Protokoll. |

Nicht in diesem Release:
- ein Weg, auf dem ein Merge-Push etwas aufschiebt;
- ein Vermerk, der zwischen Hosts reist (siehe H4).

## H — Host-Bedingung je Stack

### Aufgaben

- [x] H1: **`testing_config`.** Ein Stack darf `preflight` (argv) tragen. Der Schlüssel steht nur dann in der Stack-Konfiguration, wenn er gesetzt ist; so ändern sich `push_evidence` und Stempel bestehender Projekte nicht.
  - `preflight_timeout` gilt für alle Preflights und ist erlaubt, sobald irgendein Preflight gesetzt ist.
  - Lauf wie der globale: `cwd` ist die Wurzel, Umgebung `git_environment()`.
  - Exit `3` heißt „dieser Host kann den Stack nicht“ (`HOST_UNSUITED`). Der Befehl selbst muss 3 liefern; `make` faltet Fehler zu 2, also einen Befehl direkt nennen.
  - Jeder andere Code ungleich 0 heißt „der Host ist kaputt“.
  - Der globale Preflight bleibt unverändert.
- [x] H2: **Aufschieben nur nach dem Integrationsbranch** (beide Reviews, blocker/major). Ein Stack darf nur aufgeschoben werden, wenn
  - sein `preflight` am Integrationsref genau so steht wie im Arbeitsbaum, und
  - keine Repo-Datei, die das argv nennt (etwa `scripts/host_check.py`), im Range des Branches geändert ist.

  Sonst gilt eine 3 als „Host kaputt“ (Exit 2). Ohne lesbaren Integrationsref wird nie aufgeschoben. So kann ein Branch seinen eigenen Stack nicht für untauglich erklären; das ist dieselbe Regel wie bei `inert` in v2.84.
- [x] H3: **`test_select.run`, Branch-Klasse.** Die Preflights der Stacks laufen **vor** der Auswahl. Vorher könnte der lokale Selektor (`select`) des Stacks auf dem untauglichen Host scheitern, und der Mac-Fall bliebe abgewiesen.
  - Reihenfolge: Erst wird bestimmt, welche Stacks der Range berührt (ihre Pfade und Pin-Subjekte). Dann läuft der globale Preflight, dann der Preflight je berührtem Stack, und erst danach `plan` ohne die aufgeschobenen Stacks.
  - 0: Der Stack läuft.
  - 3 (nach H2 erlaubt): Seine Arbeit entfällt. Die Ausgabe nennt ihn: `test_select: owed on the gate host — backend (this host cannot run it; the train runs it)`.
  - Bleibt keine Arbeit übrig, ist das Ergebnis grün mit diesem Vermerk.
  - `run` meldet die aufgeschobenen Stacks an den Aufrufer zurück (Rückgabe mit `owed`), nicht nur einen Exit-Code.
- [x] H4: **Nichts wird als bestanden vermerkt.**
  - **Zertifikat:** `_certify` schreibt kein Push-Zertifikat, wenn ein Stack aufgeschoben wurde; Test 1 läuft mit `--certify` auf sauberem Baum.
  - **Stempel:** `pre_push` schreibt weder den SHA- noch den Baum-Stempel, wenn ein Stack aufgeschoben wurde, wie bei einem Skip. Ein späterer Buchhaltungs-Commit auf demselben Baum ist also kein Treffer „gates only“.
  - **Verdikt:** Es bleibt `ok`, damit der Merge-route-Hook von pre-commit nichts Neues kennen muss.
  - **Kein eigener Vermerk:** keine Datei `process-owed.jsonl`, keine Bundle-Zeile (beide Reviews: überbaut, reist nicht zwischen Klonen). Das Vorbild ist `unmapped=skip`: eine Zeile in der Ausgabe.
- [x] H5: **Merge prüft jeden Stack.**
  - **`test_select`, Merge-Klasse:** Vor `merge_suite` oder `full` läuft der Preflight jedes Stacks. Jeder Code ungleich 0, auch 3, weist ab (Exit 2, „a merge runs every stack“). Ein Merge-Zertifikat trifft weiter vorher; das ist sicher, weil es nur Zug oder `finish --tests` schreiben, und beide prüfen jetzt alle Stacks.
  - **Zug** (`train.py`): Nach dem globalen Preflight laufen alle Stack-Preflights; jeder Code ungleich 0 ist `EnvironmentRed`, niemand wird beschuldigt. Sonst läse ein kaputter Gate-Host, sobald Kenni seine Backend-Prüfungen in den Stack-Preflight verschiebt, als roter Zug mit Bisect (#209).
  - **`finish --tests`:** Vor der Suite laufen globaler und alle Stack-Preflights; jeder Code ungleich 0 merged nicht und schreibt kein Zertifikat.
- [x] H6: **Doku.**
  - `testing.md`: der Preflight je Stack, Code 3, H2 und „ein Merge schiebt nie auf“.
  - `train.md`: Der Zug prüft auch die Stack-Preflights.

### Tests (rot vor dem Fix)

1. Branch-Push, zwei Stacks, Preflight von `backend` gibt 3 und steht so am Ref: `frontend` läuft, `backend` nicht, Exit 0, der Vermerk steht in der Ausgabe, kein Push-Zertifikat (mit `--certify`), kein Stempel.
2. Derselbe Preflight gibt 1: Exit 2, kein Test lief.
3. Der Preflight steht nur im Arbeitsbaum, oder sein Skript ist im Range geändert: Eine 3 weist ab (Exit 2).
4. Der Stack hat einen `select`, der auf diesem Host scheitern würde: Bei 3 läuft `select` nicht, der Push geht durch.
5. Merge-Push: Ein Stack-Preflight gibt 3 → Exit 2, keine Suite.
6. Zug: Ein Stack-Preflight ungleich 0 → `EnvironmentRed`, kein Bisect.
7. `finish --apply --tests`: Ein Stack-Preflight ungleich 0 → kein Merge, kein Zertifikat.
8. Nach einem Aufschub trifft ein Buchhaltungs-Commit auf demselben Baum keinen Stempel.
9. Ohne Stack-Preflight ändern sich `push_evidence`, Stempel und Ausgabe nicht.
10. `testing_config`: Ein Stack-`preflight`, das kein argv ist → `ConfigError`; `preflight_timeout` nur mit Stack-Preflight ist gültig.

## S — Jeder Skip braucht einen Grund

### Aufgaben

- [x] S1: **Geltung.** Jeder Weg an den Prüfungen vorbei verlangt `PROCESS_SKIP_REASON="<Grund>"`:
  - `PROCESS_SKIP=gates|tests`;
  - `SKIP=process-gates` (pre-commit);
  - `--bypass NAME` aus einem eigenen Hook.

  `PROCESS_OWNER_OVERRIDE` trägt seinen Grund schon selbst.
- [x] S2: **Reihenfolge.** Die Grund-Prüfung kommt **nach** den Phasen- und Record-Prüfungen in `merge_route.check` und `pre_push._owner_only`, damit „aus einer dispatchten Sitzung“ die erste Ablehnung bleibt. Ohne Grund lautet sie: „a skip needs its reason: `PROCESS_SKIP_REASON=\"…\"`“.
- [x] S3: **Protokoll.** Die Zeile trägt den Grund: `PROCESS_SKIP=tests: <Grund>`, `SKIP=process-gates: <Grund>`.
- [x] S4: **Doku.**
  - `testing.md`: „Skipping“.
  - `train.md`: „Skipped gates“, der Begriff `SKIP=process-gates` bleibt.

### Tests

11. `PROCESS_SKIP=tests` ohne Grund → abgewiesen, kein Eintrag; mit Grund → angenommen, die Zeile trägt ihn.
12. `SKIP=process-gates` und `--bypass` ohne Grund → abgewiesen; mit Grund → protokolliert.
13. Aus einer dispatchten Sitzung bleibt die Ablehnung „dispatched“, mit oder ohne Grund.
14. Angepasst: `test_pre_push.py` (Skip-Fälle :159, :309, :472), `test_merge_guard_push.py:174`, `test_merge_route.py:267/:275` bekommen einen Grund.

## Regressions-Linse

- **„A missing check reported as passed“:** Ein aufgeschobener Stack heißt nie grün ohne Vermerk. Die Ausgabe nennt ihn, ein Zertifikat entsteht nicht, der Stempel trägt ihn.
- **Merge-Weg:** Merge-Push und Zug fahren jeden Stack. Ein Host, der einen Stack nicht kann, kann nicht mergen.
- **Preflight-Semantik:** Der globale Preflight bleibt unverändert. Neu ist nur ein Code mit Bedeutung beim Preflight je Stack, und nur auf dem Branch-Push und nur so, wie der Integrationsbranch ihn kennt.
- **Zug als Umgebungsprüfung (#209):** Er prüft jetzt auch die Stack-Preflights, ein kaputter Gate-Host bleibt „Umgebung“.
- **Owner-Skip:** Er wird strenger (Pflichtgrund), nie lockerer.

## Update

Reines Update. Ohne Stack-`preflight` ändert sich nichts außer dem Pflichtgrund für jeden Skip (`PROCESS_SKIP_REASON`). Kenni trägt den Host-Check für `backend` als Stack-Preflight ein (Exit 3 auf dem Mac) und kann den globalen Preflight dann auf das beschränken, was jeder Host können muss.
