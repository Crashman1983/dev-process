## Code-Review und Refute

- **Volle Suite** auf 00356ce: 4226 grün, 1 übersprungen.
- **Code-Review (DeepSeek):** block, 1 Major: ein erster Start war nur ein lokaler Record, den der andere Host nie sieht. Behoben mit dem Bericht `started` (6d58733); dazu ruhende Arbeit in Tower und `intake` gezeigt, `done` des Zugs auch ohne `--push` veröffentlicht.
- **Refute 1 (Claude, mit zwei Klonen nachgestellt):** block — derselbe Blocker; dazu als Major eine Fortsetzung vom anderen Host als erster Start geprüft. Behoben (ac29326); nur ein Block mit WIP-Grenze schaltet Prüfung, Netzschritt und Veröffentlichen ein; `PROCESS_TRACK`/`PROCESS_REPORT_SYNC` in Tests entfernt; ein falscher Verweis in `testing.md` (dcb0398).
- **Refute 2 (Claude, zwei Klone):** Blocker für lokale Starts bestätigt behoben; Major: eine an einen anderen Host übergebene erste Phase veröffentlichte keinen Anspruch. Behoben mit den Minors (00356ce): jeder Weg eines ersten Starts veröffentlicht `started`; begonnen heißt nur ein `started` eines Hosts (ein `done` oder ein Steward-Bericht befreit nicht); `stop` veröffentlicht sein `idle`; die `wip`-Zeile folgt derselben Schwelle; die Warteschlange fragt `--track` wie `start`.
- **Bewusst offen:** `dispatch.py track` wirkt auf dem Host, auf dem es läuft; laufende Worker tragen den Track erst ab ihrer nächsten Phase. Ein `--over-wip`-Ereignis wird geschrieben, bevor der Rest des Starts scheitern kann. `drain` puffert die Ausgabe je Start.
