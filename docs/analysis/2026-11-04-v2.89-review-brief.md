## What to check

1. **No change without `preboard`:** same `_sh` calls, verdicts, merges, certificates, blames, rows (apart from the zero `preboard` phase).
2. **No wrong drop:**
   - a red or unrunnable base;
   - a broken host;
   - a stale candidate tip;
   - plan settling in the probe tree;
   - residue between the run and its rerun;
   - a conflict;
   - a timeout;
   - a failed worktree add.

   None of these may report a candidate `blocked`.
3. **Cleanup and isolation:** the second worktree and its `train/<stamp>-preboard` branch on every exit, including exceptions. Interaction with the main train worktree, `_cleanup`, the BaseException path, a leftover from a killed run, and dispatch worktrees.
4. **Carrier and rows:**
   - `outcome["result"] = "preboard"`;
   - `aboard` keeps its start count;
   - `preboard` seconds vs `preboard_checks`;
   - the v2.88 `measure`/`rounds` carrier still ends a red preflight as `environment`;
   - `train-phases` (telemetry `process_kpis.py`) reads all of it, old rows too.
5. **Config:** `preboard`/`preboard_timeout` validation, `--preboard ""`, `main()` plumbing.
6. **Docs:** do `train.md` and `testing.md` say what the code does?
