## Your role

You are an independent code reviewer with a refuter's stance: find defects someone would hit. Do not implement anything. Where this brief and the repository disagree, the repository wins. Template files live under `template/`. Some names contain Jinja, so quote them.

- **Diff:** `git diff d1a47795..HEAD -- template tools tests` on branch `claude/intelligent-lamport-2t1dxv`.

## What to check

1. **S2: record texts read once per blob** (`check_review.py` `record_texts`, `_blob_texts`, `_known_work`, `_plans_at_ref`; `train._covers`).
   - Is the cache key complete (root, path, blob)?
   - The worktree read (`ref=None`) must never be memoised.
   - Is the `cat-file --batch` parsing exact (size header, newlines, NUL, empty blob, missing object, gitlink, short read)?
   - Can a partial result reach the review gate's read (`check_review.py` around 1903) as a passing answer?
2. **S6: one `merge-tree --stdin`** (`check_review._auto_merges`, `train.conflict_hints`).
   - Does the batch match the single-pair results?
   - Is the cache prefill key and order identical to `_auto_merge`'s?
   - Fallback on exit ≠ 0, timeout, count mismatch or status mismatch.
   - Can a prefilled entry mislead `integration_conflict` or other callers?
3. **S7: the own-family rule at the snapshot** (`train._covers(base=)`, `_settle_plans`). Is the right commit used by every caller, and are there no stale caches?
4. **S1: merged branches skipped** (`candidates`, `_listed_refs`, `_snapshot`, `no_lead`).
   - A branch moved after the snapshot.
   - `train/*` and `local` branches.
   - Does the count agree between `plan` and `run`?
5. **S3 and S4** (`placed=` through `_branch_issues`/`_own_plans`/`_deviations` to `dispatch.branch_issues`/`issues_of`; phase `plan` in `PHASES` and `process_kpis._TRAIN_PHASES`).
   - Do the defaults keep the old behaviour?
   - Old `phases.jsonl` rows without `plan`.
6. **S5: a stack needs shared commits** (`_stacked_renames`, `_commits_beyond`).
   - An unreadable `rev-list` must stay fail-closed.
   - The `merge-base` order must be deterministic.
   - #201 (one plan under two names) must still work for a real stack.
7. **R1: reasons at every exit** (`left_behind`, `_candidate_lines`, `_no_lead_lines`, `_stay`, `last-hold.log`).
   - The wording must match `plan` exactly.
   - The log must be written before the first build.
   - `last-hold.log` must be overwritten, not appended.
   - An unwritable common dir.
8. **Docs:** `train.md`, "Who stays behind, and why" and "Planning cost", and the phase list.
9. **`tools/bench_train_plan.py`:** does it build what it claims, and are the times honest?
