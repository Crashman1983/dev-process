## Paket N — Entwurf (#262, #263-Folgefrage)

**Befund (Code, v2.74.2):**
- `template_verify._verify` setzt `acknowledged` nur bei `ack.base == base` (Fork-Point von Tip und Integrations-Ref) und `ack.release == new_sha`.
- `check_review.template_review_findings` zählt nur volle Pässe mit `r.base == update.base`.
- Die gewöhnliche Abdeckung (`_history`, Step B) verträgt einen weitergelaufenen main schon: Ein Review zählt ganz, wenn seine Basis auf main liegt und git den Merge selbst sauber auflöst (#158). Strikt ist allein die Basis-Gleichheit der beiden Update-Prüfungen. Ein Zug, der auf einen weitergelaufenen main merged, verliert damit Ack und Update-REVIEW, auch wenn main das Update nicht berührt hat (Kenni #2631, #2621-Zug).

**Entscheidungen (nach Plan-Review Runde 1):**
- N1 — **Ein Owner** in `template_verify`: `carried_base(root, old_base, base, paths) -> str | None`. Rückgabe ist None, wenn die alte Basis trägt, sonst der Grund. Sie trägt, wenn:
  - `old_base == base` ist, oder `old_base` ein Vorfahr von `base` (`merge-base --is-ancestor`);
  - `git diff --name-only --no-renames -z old_base base` (mit `git_environment()`, Namen über `os.fsdecode`) keinen Pfad der Menge `{.copier-answers.yml, Ack-Datei, .process-owned} ∪ identical ∪ project_delta` trifft. Die Menge kommt aus dem Bericht an der neuen Basis.
  - `--no-renames` ist nötig: Sonst sähe eine Umbenennung auf main nur den neuen Namen (Plan-Review M1).
  - Die Render-Pfade gehören nicht in die Menge. Jeder Pfad, dessen Render sich zwischen den Releases ändert, steht schon in `identical ∪ project_delta` (`template_verify.py:229`). Die übrigen Render-Pfade (`CLAUDE.md`, `PRODUCT.md`, `adr/README.md` …) ändert jeder Kenni-Zug. Mit ihnen wären zwei von drei echten Re-Acks bei Kenni wieder verfallen (Plan-Review M2).
  - Gründe für „trägt nicht“:
    - `old base … is not an ancestor of …`;
    - `old base … is not in this clone (shallow?)` — eigene Meldung, weil Cloud-Sessions flach klonen (m2);
    - `main changed <path> since …`;
    - ein git-Fehler (fail closed).
- N2 — **Ack:** Das Ack ist bestätigt bei `release == new_sha`, gesetztem `owner` und `carried_base(ack.base, base) is None`. Dazu kommt ein **Fingerabdruck** im Ack, den `--ack` künftig mitschreibt: `old_release`, sortiert `identical`, sortiert `project_delta`, `migration`. Ein Ack mit anderer Basis trägt nur bei gleichem Fingerabdruck; das vergleicht das berechnete Ergebnis an beiden Basen, ohne zweiten Render. Ein Ack ohne Fingerabdruck (heutige Dateien) trägt nur bei gleicher Basis, also wie heute. Neuer Berichtsschlüssel `ack_expired`: der Grund, den Gate, finish und Zug nennen.
- N3 — **Update-REVIEW:** `template_review_findings` nimmt volle Pässe mit `carried_base(r.base, update.base, paths) is None` statt Gleichheit. REVIEW-Zeilen haben keinen Fingerabdruck. Die Pfadprüfung reicht, weil `_unreviewed_paths(root, r.head, tip, …, r.base) == set()` den Inhalt weiter prüft.
- N4 — **Ein Owner, alle Leser.** `update['acknowledged']` lesen:
  - `verified_template_plan` (`check_review.py:2597`; dessen Ausnahme trägt jetzt mit dem Ack);
  - `template_review_findings` (`:2609`);
  - das Gate (`:2740`);
  - `finish.py:180`;
  - `train.py:430`.

  Die Basis-Gleichheit für REVIEW gibt es nur an `check_review.py:2616`. `invalid_records`/`_base_problem` (`:978`) betreffen den eigenen Fork-Point eines Records und bleiben, wie sie sind. `make_review_bundle` und `template_update.py` binden keine Basis.
- N5 — **#263-Folgefrage (Zug):** Jeder Retry-Zweig hält fest, was wirklich lief (`ran`), und die Meldung folgt daraus (Plan-Review M3):
  - Der Projekt-Befehl `--retry` lief: „green under the retry command `<retry>` (a subset), red under the suite — flaky, or the two runs differ (flags, environment)“.
  - Der Retry-Befehl fehlte, es gab einen vollen Neuaufbau mit demselben Suite-Befehl: „red then green on the identical tree — flaky suite“, wie heute.
  - Die Gates waren rot, die Suite lief danach erstmals grün: kein Flaky-Satz über die Suite.

  Der Merge läuft weiter wie heute; pre-push fängt einen echten Unterschied mit der vollen `merge_suite` ab.
- N6 — **zurückgenommen (2026-10-19, beim Bauen):** `tests/test_template_verify.py::test_finish_and_train_declare_pyyaml_the_gate_imports_it_lazily` hält eine bewusste Entscheidung aus #170 fest. `check_review` bleibt ohne Kopf: Der Gate-Runner startet es mit seinem eigenen Interpreter, der PyYAML trägt. Ein Kopf ließe jeden Gate-Lauf über `uv run --script` neu auflösen, das ist langsamer und braucht bei leerem Cache Netz. Der Einzelaufruf des Stewards war ein Diagnose-Umweg und kein Pfad, den ein Hook geht. #262 AC-4 entfällt mit dieser Begründung. Ursprünglicher Entwurf:
  - N6-alt — **Robustheit:** `check_review.py` deklariert `PyYAML` im PEP-723-Kopf. Das wirkt nur für den Kindstart über `gate_invoke.child_argv` und für einen eigenen Lauf mit `uv run --script`. **AC (EARS):**
- AC-N1: When the branch merges a main that moved only through product files (replay of Kenni `735b06 → 3ce083`), an ack with matching fingerprint shall stay acknowledged, and a full update REVIEW on the older base shall still cover the update.
- AC-N2: When main changed a path of the update set (`identical`, `project_delta`, `.copier-answers.yml`, `.process-owned`, the ack file) since the old base, the ack and the REVIEW shall expire, and `ack_expired`/the finding shall name the path. This also holds when main renamed such a path.
- AC-N3: Nothing shall carry when:
  - the release SHA differs;
  - the fingerprint differs;
  - the ack has no fingerprint and its base differs;
  - the old base is no ancestor (a REVIEW base above main, a rebase);
  - the old base is missing from a shallow clone, with its own message;
  - git cannot tell.
- AC-N4: A carried REVIEW whose head does not contain the update shall stay blocked by `_unreviewed_paths`. A migration update needs a carried Tier 3 REVIEW.
- AC-N5: `template_update.py --verify` (worktree mode) shall report a carried ack as acknowledged.
- AC-N6: The train's message shall name what the retry ran: the `--retry` command, a full rebuild with the same suite command, or the suite after red gates. It shall call it flaky only in the second case.
- AC-N7: The gate runner shall start `check_review.py` with its declared PyYAML when the runner's own interpreter lacks it.
- Existing test `test_verify_binds_the_fork_point_when_integration_moved_on` (`tests/test_template_verify.py:643`) stays. A new case lets the branch really merge the moved main.
