## What changed against round 1 (verify each)

**B, inert changes.**
- **The certificate is untouched.** `evidence_tree` is not changed, which removes the second glob matcher.
- **"Inert" is read only at the integration ref.** No ref, an unreadable ref or a broken file means nothing is inert.
- **Protected paths are never inert:**
  - everything `is_gate_path` knows;
  - all of `docs/process/` (overlays such as `review.local.md`, the registry, the policies);
  - `.claude/`, `.github/`, `.specify/`, `.copier-answers.yml`;
  - any file `testing.local.json` names.
- **Test inputs are never inert.** An inert glob that covers a stack path, pin or map target is a `ConfigError`.
- **One owner, `quiet_paths`,** for `pre_push` and `finish`; both sides of a rename count.
- **`finish` merges a quiet range without a test run** and writes no merge certificate.

**C, ui-check.**
- **Its own module `ui_check`,** default on and added to older manifests by `_migrate` (the `sbom` precedent), independent of `design_contracts`.
- **UI is detected from `areas.ui`.**
- **Attribution per plan:** a plan owes the block only when the paths *it* names touch UI (tasks, trace, spec), never the whole branch diff.
- **Start mode:** shadow **with `observe`**, so the sentinel leaves it alone. A same-named local gate keeps its mode. Promotion is `gate_modes.py restore`.
- **Lasting grandfathering:** plans first added before `ui_check_from` (the day the module entered the manifest, read from git) stay at a note even after promotion.
- **The parser is fence-aware.**
- **Generic rules from the Kenni v5.3 alignment:**
  - every check needs a negative test;
  - DoR R5 (reuse proof) applies on every platform;
  - the UI source is tool-neutral in the repository.
